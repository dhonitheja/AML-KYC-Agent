# CS-009: llm.py (new)

## Description
Model abstraction used only by CS-008. A deterministic offline stub is the default; a self-hosted model server inside the deployment (`local`) and the Anthropic Messages API (synthetic data only, gated in CS-008) are opt-in. A retry wrapper bounds every call. Env parsing lives in CS-008 startup; `llm.py` receives validated values.

## Public Interface
- Protocol `LLM`: `complete(system: str, user: str) -> tuple[str, str]` returning `(text, model_id)`.
- `PROMPT_VERSION = "investigation-prompt-v2"` (bumped for the findings schema and the no-unstated-amounts/names rule; also owned by CS-008 `render_prompt`; defined once in `llm.py` and imported).
- `StubLLM()`: no network, no credentials, deterministic. It parses the `<evidence>` JSON in `user`; collects every transaction id in the evidence (transaction + history); `recommendation = "escalate_for_review"` if any rule has `points >= 60` or any screening has a non-empty `hits`, else `"no_further_action_suggested"`; output uses literal templates with only lowercase prose, ids and fired rule names (no `$` amounts, no double quotes; `screening hit` only when a hit exists; never the sanctions words otherwise). `summary` = "transaction {id} scored {score} with fired rules: {comma-separated rule names}." (rule list "none" when nothing fired) plus, if a hit exists, " payment screening recorded a screening hit."; `cited_transaction_ids` = the evidence transaction id plus history ids (sorted). Findings: one per fired rule, `statement` "{rule} fired for {points} points.", `rule` = that name, citing that rule's evidence ids intersected with `evidence_ids` (falling back to the alerted id); if a hit exists, a finding "screening hit recorded for counterparty screening." citing the alerted id (`rule` null); if neither a rule nor a hit exists, one finding "no rules fired for this transaction." citing the alerted id (Draft requires at least 1 finding). The first finding also cites any summary ids not otherwise covered; at most 10 findings. `recommendation` = `escalate_for_review` if any rule has `points >= 60` or any hit, else `no_further_action_suggested`. These templates pass all four checks: no `$` (amounts), no double quotes (counterparties), every snake_case token in text is a fired rule name (rules; the recommendation value appears only in the `recommendation` field), and sanctions terms appear only via "screening hit" when a hit exists (assumes fired rule names are lowercase snake_case without sanctions words). Returns `(json_text, "stub-v1")`. Identical evidence yields byte-identical output (FR-010.2). If the evidence cannot be parsed it raises, which exercises the model_failure path. Output shape is the CS-008 `Draft` (summary, recommendation, cited_transaction_ids, findings). Test hook: a stub subclass or flag may be forced to raise or to cite a fabricated id or emit an ungrounded amount, name, rule or sanctions claim, and supports a per-attempt script (e.g. attempt 1 returns ungrounded output, attempt 2 raises) to exercise FR-010.4 AC-5 / FR-011.2 AC-7.
- `AnthropicLLM(api_key, model, timeout)`: `anthropic.Anthropic(api_key=api_key, max_retries=0, timeout=timeout)`; `complete` calls `client.messages.create(model=model, max_tokens=16000, output_config={"effort": "low"}, system=system, messages=[{"role":"user","content":user}])` with no `tools`, no streaming; returns `("".join(text blocks), response.model)`. Non-text or empty content is an error. `stop_reason` `refusal` or `max_tokens` is a non-retryable failure (`last_reason=model_failure`); no `fallbacks` parameter is sent and no `temperature` is sent (current models reject sampling parameters with a 400).
- `LocalLLM(url, model, timeout)`: backend for a self-hosted server inside the Compose deployment (FR-010.5, DI-011). Recommended server: Ollama's HTTP API. `complete` does one `POST {url}/api/chat` with JSON `{"model": model, "stream": false, "format": "json", "messages": [{"role":"system","content":system},{"role":"user","content":user}], "options": {"temperature": 0, "num_predict": 4096}}`; no tools, no streaming, no auth header, no API key. It uses stdlib `urllib.request` and `json`; no new dependency (one small JSON body does not justify httpx/requests, and adding one would widen the NFR-008 AC-5 grep scope). Returns `(response["message"]["content"], model)` where the model id is `LLM_MODEL` as configured (the server echo is ignored, so `model_version = LLM_MODEL`, FR-010.5 AC-3). Missing or non-string content, a non-JSON body, or an `error` key is an error. `done_reason == "length"` is a non-retryable failure (`last_reason=model_failure`), like `max_tokens` in anthropic mode. The prompt, `PROMPT_VERSION`, strict `validate_draft` and `check_grounding` are the same as in other modes (they run in `complete_with_retry`, not in the backend). `format: "json"` constrains syntax only; schema and grounding validation stay authoritative.
  - Output cap (LLM10): `options.num_predict = 4096` tokens. The strict `Draft` schema is at most about 2000 chars summary plus 10 findings of 300 chars plus ids (roughly 1500 to 2500 tokens), so 4096 leaves headroom and bounds runaway generation. Truncation shows up as `done_reason == "length"` (non-retryable). Each backend exposes `params()` (anthropic `{max_tokens:16000, effort:"low"}`, local `{temperature:0, format:"json", num_predict:4096}`, stub `{}`) used by CS-008 `params.request`.
  - Opener: built once with `urllib.request.build_opener(urllib.request.ProxyHandler({}), _NoRedirect)` where `_NoRedirect` is an `HTTPRedirectHandler` subclass whose `redirect_request` returns None (a 3xx then surfaces as `HTTPError` and is non-retryable). `build_opener` adds `HTTPRedirectHandler` by default, so the explicit subclass is required to override it; the empty `ProxyHandler` stops `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` env vars rerouting the call. `urlopen` is not used (it uses the global opener).
  - A 200 response with an `error` key, a non-JSON body, or missing/empty/non-string `message.content` is a retryable validation failure (counts as an attempt, `error="validation"`, `last_reason=model_failure`), consistent with FR-010.4 (schema-invalid output is `model_failure`).
  - Error mapping, sanitized to `(class name, status)` like `AnthropicLLM` (the urllib exception is caught, reduced and not chained): connection refused, DNS failure, timeout, connection reset or remote disconnect are retryable; HTTP 429 and 5xx retryable; other 4xx (400, 401, 403, 404, 422; 404 usually means the model is not present) non-retryable. Redirects are not followed (opener without `HTTPRedirectHandler`), so a response cannot steer the call off the configured host. An unreachable server gives `model_failure` after `LLM_MAX_ATTEMPTS` (FR-010.5 AC-4). URL, request body and response text are never logged or stored.
- `complete_with_retry(llm, system, user, validate, max_attempts, sleep=time.sleep, rng=random.random) -> (text, model_id, attempts) | Failure(attempts)`: calls `llm.complete`, then `validate(text)`; success returns immediately.
  - Retries: timeouts, connection errors, HTTP 429, 5xx, validation failures and grounding failures (the model may answer differently; the same prompt is still allowed to retry per FR-010.4).
  - Not retried: other 4xx (400, 401, 403, 404, 422) fail immediately.
  - Backoff: `min(30, 2**(attempt-1)) * (0.5 + rng())` seconds between attempts (exponential with jitter); injectable `sleep`/`rng` keep tests fast.
  - Never raises on model failure: returns `Failure(attempts)`. Exceptions are reduced to `(exception class name, status_code)` before any logging or storage; the original exception is not chained, logged or stored (it can contain request headers or text).

## Internal Data Structures
`Failure(attempts:int, error:str, failed_checks:list[str]=[], last_reason)` where `error` is `"<ExcType>[:<status>]"`, e.g. `APITimeoutError`, `APIStatusError:429`, `validation`, `grounding`. `failed_checks` carries the CS-008 `check_grounding` names so CS-008 can emit `skipped(grounding_failure)` rather than `skipped(model_failure)`. Each attempt overwrites `error` and `failed_checks`; `last_reason` in {`model_failure`, `grounding_failure`} is set from the LAST attempt only, and CS-008 classifies by it. A non-retryable 4xx ends the loop immediately with `last_reason=model_failure`. The `validate` callable returns None on success, else an error tag plus optional failed checks.

## Key Algorithms
Bounded loop of at most `LLM_MAX_ATTEMPTS`; worst-case wall time = attempts * timeout + sum of backoffs, which is the figure CS-008 uses to size `max.poll.interval.ms` (+ 60 s margin). The SDK's own retries are disabled (`max_retries=0`) so the bound is exact and no hidden attempt multiplies cost or egress.

## Component Interactions
Called by CS-008 outside any DB transaction. In anthropic mode talks HTTPS to the Anthropic API (DI-010); in local mode talks plain HTTP to the model server on the internal network (DI-011); in stub mode has zero network dependencies, which keeps CI keyless and offline (NFR-007).

## Invariants
- `LocalLLM` holds no secret and sends no `Authorization` header; reachability is limited by the internal network (NFR-008.1), and the URL host is not validated (FR-010.5 AC-5). `llm.py` now imports `urllib` (stdlib, internal URL only), so the NFR-008 AC-5 grep scope must treat `llm.py` as a permitted network module and name it explicitly.
- The API key exists only in the `AnthropicLLM` instance; it is never in prompts, params, audit rows, logs or exception text.
- `model_version` stored is the provider-returned model id (`response.model`) in anthropic, the configured `LLM_MODEL` in local, `stub-v1` in stub.
- Fixed request parameters per backend. Anthropic: `max_tokens=16000`, effort `low`, no `temperature`. Local: `temperature=0`, `format=json`, `num_predict=4096`. No tools in any mode: the model cannot act, only return text.
- The `anthropic` import is lazy (only in anthropic mode) so stub deployments need not load it.

## Traceability
FR-011 (stub emits grounded findings; grounding failures use the same bounded retry loop, ADR-027), FR-010.1 (mode), FR-010.5 (LocalLLM, `model_version = LLM_MODEL`, unreachable server gives model_failure), FR-010.2 (stub), FR-010.3 (config, versions), FR-010.4 (bounded retry, failure = skipped), FR-009.4 (validation inside the retry loop); NFR-005 (no tools, advisory), NFR-006 (key and error sanitation), NFR-007 (stub default), NFR-008 (local backend keeps data inside the deployment; no key in local).
